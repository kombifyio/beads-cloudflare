# Portfolio dashboard

Open `/dashboard/` on the store's public origin. The same Worker serves the page, the read-only portfolio API and the tracker API (no separate Pages deployment or second tracker database).

Sign-in uses the configured Cloudflare Access OIDC provider: a confidential OAuth client requests only `beads:read`, PKCE and a browser-bound state cookie protect the return, and OAuth tokens stay in server-side KV. Browsers get an opaque HttpOnly, Secure, SameSite cookie lasting at most one hour; sign-out is a same-origin POST. Every API call reuses the provider's scope and tracker authorization. API keys can read `/portfolio/overview` directly within their scopes and tracker restrictions; an administrator token is not a portfolio credential. The public HTML contains no tracker data.

## Configuration

`PORTFOLIO_TITLE` labels the overview. `PORTFOLIO_REPOSITORIES` is a JSON array of `{id, name, tracker, group}` (IDs and trackers use the tracker ID grammar); empty derives the catalog from `GITHUB_REPOSITORIES`. Several names for one tracker become aliases counted once. Metadata never grants access, and a deployment with no catalog reports an empty overview instead of discovering unauthorized trackers. `PORTFOLIO_LABELS` optionally names catalog groups and roadmap phases as `{"groups": {...}, "phases": {...}}`, each key mapping to a name or to names per language (`{"de": "…", "en": "…"}`); keys without a name show as written, and malformed labels fail the overview instead of being ignored. The UI carries no deployment-specific names.

`PORTFOLIO_LABELS` also takes optional `conventions`, which name the tracker labels that carry meaning. Each key that is left out keeps its neutral default:

| Key | Meaning | Default |
| --- | --- | --- |
| `repo_prefix` | In a shared tracker, a label `<prefix><name>` or `<prefix><owner>/<name>` on a record or an ancestor names the owning repository; a roadmap's epics in a shared tracker match it too | `""` (off: every record belongs to its tracker's catalog repository; a roadmap in a shared tracker then matches only epics titled `[name] …`) |
| `milestone_label` | An epic with this label is a milestone (any record with it is a planning container, never work); native `milestone` records always are | `"milestone"` |
| `phase_prefix` | A label `<prefix><key>` on a milestone names its phase; the first label with a valid key wins; phases sort in the order of `phases`, then naturally | `"phase:"` |
| `waiting_labels` | Up to 32 exact labels or `prefix*` patterns (at least one more character) that put work under *Needs attention* as waiting; `[]` turns waiting labels off | `["blocked-*"]` |

A prefix is 2 to 32 characters (letters, digits, `_`, `.`, `-`) ending in `:`, `/` or `=`. In `ROADMAP.md` a milestone's phase is the key after `Central:` or a line starting with `Phase:` (or a `Central` or `Phase` table column).

Example: `{"phases": {"alpha": "Alpha", "beta": "Beta"}, "conventions": {"repo_prefix": "repo:", "waiting_labels": ["blocked-*", "needs-review"]}}`. Public setup uses `BEADS_PORTFOLIO_TITLE`, `BEADS_PORTFOLIO_REPOSITORIES` and `BEADS_PORTFOLIO_LABELS` with `cloudflare.config.ts`.

## Views

The page opens on **Today**. One filter row (area, repository, free-text search) scopes Today, Projects and Metrics alike and is remembered per browser; the language choice is remembered too. Light and dark follow the system setting.

- **Focus data.** `/portfolio/focus` (schema `beads.focus.v1`) makes one revision-stable read of every admitted tracker and returns every nonterminal record, the work closed in the last 7 days and a created/done/dropped flow per UTC day and repository for 30 days. Ephemeral, template, infrastructure and gate records are excluded; epics and milestones are flagged as containers and never count as work. With a configured `repo_prefix`, the repository is the first such label on the record or an ancestor, else the catalog repository. Pinned records are standing context and never count. A close reason naming a superseded, obsolete, duplicate, retired, moved, migrated, abandoned, out-of-scope, low-value, not-planned or won't-fix record counts as dropped, every other close as done. The report also names the owning repository of every epic and milestone, closed ones included. Each row carries native ready membership, native or explicit blockers, the open records it blocks in the same tracker, the first label matching `waiting_labels`, the claim holder with its live state and whether the claim lapsed. The report is cached in KV for two minutes per tracker set (`?fresh=true` bypasses); an incomplete read is never cached and names its unread trackers.
- **Today.** Six tiles: open work with its net change over 7 days, P0 (and P1) work, work in progress, work that needs attention, work closed today and work done in 7 days against the previous week. Below, four lists: *Do next* holds ready, unblocked open work that nobody holds, overdue first, then by priority, work it unblocks and age; *Needs attention* holds stalled work (a lapsed claim, or in-progress work without a live claim and without change for two days), blocked work, decisions and work behind a waiting label; *In progress* shows holder and duration; *Closed* groups this week's completions by local day, dropped work on request. Work held back only by open dependencies counts in the attention tile's footnote, not in a list.
- **Projects.** Milestones from `/portfolio/milestones` (native milestones and epics with `milestone_label`) grouped by their `phase_prefix` label, reported in the field `central`: phase tiles show closed milestones and closed beads, a click filters the table. A milestone whose beads are all closed but whose epic is still open shows as *all beads done*. The summary counts open beads outside any milestone.
- **Metrics.** Created, done and dropped work in a 7, 14 or 30 day window, the net backlog change, done work per day and the median age of open work; a column-and-line chart of done and created work per day; the measured daily history of active beads (the Dolt archive when configured); a sortable repository table (open, P0, P1, in progress, attention, created, done and net in 7 days) whose rows filter Today. Every chart has a table view and keyboard-reachable values.
- **Scopes.** The Metrics view ends with the scope table, filtered by the selected area. `/portfolio/scopes` returns label and issue-type counts (all and closed) per authorized repository; labels overlap, so a task with two labels counts in both. An unreadable repository is listed as unavailable, never estimated.
- **Modules.** A roadmap's *Tasks & modules* button opens the tracker's modules and task list. `/portfolio/repositories/{id}/modules` treats epics as modules: each non-epic issue counts toward every epic above it in its parent chain; work without an epic ancestor is unfiled. It reads the authorized brief listing (at most 40 pages of 500, `truncated` beyond) and caches the per-tracker projection in KV for five minutes (`?fresh=true` bypasses).
- **Roadmaps.** The Roadmap section renders a repository's `ROADMAP.md` live from GitHub for repositories in the catalog, mapped to a tracker in `GITHUB_REPOSITORIES` and readable by the GitHub App in `GITHUB_READ_APP`. The Worker signs a short-lived installation token (`contents: read`, memory only) with the App key from the `GITHUB_READ_APP_KEY` secret (Secrets Store binding or plain secret); without it the API answers `503 roadmap_source_unconfigured`. Each `## vX.Y.Z` (or `###`) section is a milestone card; task-list items form its checklist, grouped by bold labels or sub-headings; `(pulled forward from vX.Y.Z)`, `(deferred to vX.Y.Z)` or a `Deferred:` prefix carry a marker, and a completed item after the current milestone is marked as worked ahead (current = the `## Current Focus` target, else the first unfinished). Beads join by the section's named epic (``Beads epic: `id` ``), else a `milestone` epic of the same version; a card counts the epic's descendants plus beads labelled `blocks:v<version>` and lists the open ones, blocking bugs first. Unnamed milestone epics are shown separately. The text view renders the whole file; only `http(s)` links are followed. Responses cache for five minutes (Refresh bypasses). `/portfolio/roadmaps` lists sources, `/portfolio/roadmaps/{id}` returns one parsed roadmap.

- **State.** With `STATE_PAGE` set to `{ "repository": "owner/name", "path": "<dir>/state-page.json", "tracker": "<tracker-id>" }`, `/portfolio/state` reads that generated JSON page from the repository's default branch through the `GITHUB_READ_APP` reader and the State tab appears. It shows headline numbers with trend, measures with baseline and target, products with stable, live and preview versions, journeys, per-store work counts (live tracker counts when the page reports them unavailable) and the page's collectors. Only viewers who may read the configured tracker receive the page; everyone else, and every deployment without `STATE_PAGE`, gets `404` and no State tab. Only a document whose `kind` is `state-page` or ends in `.state-page`, with `schema_version` 1, is accepted. Responses cache for five minutes in KV (Refresh bypasses).

## Metrics and history

Counts cover all durable issues (templates and infrastructure included) and exclude ephemeral/no-history records; details use the same population. Blocked is the explicit blocked status; Ready is the native ready-work count, whose rules intentionally differ; Active is every non-closed record; Unassigned and P0/P1 count non-closed durable records; closure percentage is closed / total, not product readiness.

An hourly trigger (minute 17) observes all configured trackers and keeps the latest complete observation per UTC day for 400 days in KV; an incomplete capture fails and cannot overwrite a complete day. Current reads mark unavailable repositories and partial totals; no past is invented from imported creation dates, and current measurements and saved observations are labeled separately. Scheduled failures show in Worker observability. An optional private deployment adapter can provide a labeled Dolt archive: original dates and coverage are kept, authorization still filters every repository, and the UI never merges it into Cloudflare history.

## Development and delivery

Execute `collectPortfolio` with authenticated read-only requests against the live tracker and render the exported page/client through a loopback development server; do not copy or emulate the database. The session regression rejects unsafe requests before any storage access: `pnpm exec vitest run test/dashboard-session.test.ts`, then typecheck, deployment-config validation and the public export gate. Deploy through the store's governed delivery path, preserving Worker name, Durable Object identity and migration history, and verify the protected overview, shared-identity login, logout and a scheduled capture after activation; a source build does not prove those production boundaries.
